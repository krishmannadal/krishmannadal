# Contribution snake

The profile's purple snake uses the actual GitHub contribution calendar for
`krishmannadal`, generated by [Platane/snk](https://github.com/Platane/snk).
It does not add or change contribution data.

The workflow checks hourly, on manual dispatch, and after profile-repository pushes. Generated light/dark SVGs and static fallbacks are committed under
`assets/contributions/`; no external image widget or personal access token is
needed. GitHub's ordinary workflow token reads the calendar and commits assets.
Updates may be delayed by GitHub indexing, its scheduler or image cache. The
workflow cannot receive push events from every other repository: hourly polling
picks up their eligible contributions once GitHub records them. It commits only
when generated content changes, and ignores generated-only pushes.

This is a rolling 12-month calendar, not the native January–December year view.
README content cannot replace or overlay GitHub's built-in graph. The animation
removes cells during playback; the still shows the full calendar.

`tools/contribution_calendar.py` independently fetches the same GitHub GraphQL
calendar and checks every day's level against the snake's initial cells before
publishing. It adds actual month/weekday labels, the real total and exact date
range. The source calendar is committed as `calendar.json`; no token is saved.

`tools/snake_static.py` extracts the same grid's original cell colors into real
non-animated SVGs. The README selects these for reduced-motion preferences and
also links a still explicitly. All third-party actions are pinned to commit SHAs.

To refresh manually, open **Actions → Contribution snake → Run workflow** on
`main`. If a run fails, inspect its log; the previously committed images remain
available. Avoid replacing them with someone else's contribution graph.
